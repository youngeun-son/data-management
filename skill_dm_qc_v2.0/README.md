# DM QC 자동화 도구

임상 데이터의 기본적인 품질 검증(Data Management Quality Control)을 자동화하는 Streamlit 기반 도구입니다.

> 데모데이터를 활용하여 실제 검증 진행 단계를 보여줍니다.

## 1. 주요 기능

다음 항목을 자동으로 검증합니다.

| 검증 항목   | 설명                                       |
| ------- | ---------------------------------------- |
| 변수명 대조  | `rawdata`와 `codebook`의 변수명이 일치하는지 확인합니다. |
| 코드값 검증  | 입력값이 코드북에 정의된 허용값 또는 숫자 범위를 벗어났는지 확인합니다. |
| 방문 누락   | 대상자별로 예상되는 방문이 누락되었는지 확인합니다.             |
| 공통값 비교  | 동일 대상자의 공통 정보가 시트마다 다르게 입력되었는지 확인합니다.    |
| 방문일 순서  | 방문일이 설정한 방문 순서에 맞게 입력되었는지 확인합니다.         |
| 날짜 선후관계 | 두 날짜가 설정한 선후관계 규칙을 만족하는지 확인합니다.          |

검증 결과 외에도 다음 자료를 제공합니다.

* 자유입력 변수의 고유 입력값 목록
* 시트별 입력 패턴
* 전체 오류 목록 Excel 파일
* 추출 결과 Excel 파일

## 2. 사용 시 필요한 파일

### 필수 파일

#### `rawdata`

QC를 수행할 원본 데이터입니다.

* Excel 형식으로 준비합니다.
* 여러 시트로 구성할 수 있습니다.
* 각 시트에는 대상자 식별 변수와 검증에 필요한 변수가 포함되어야 합니다.
* 실제 임상 데이터는 사용자가 별도로 준비해야 합니다.

#### `codebook`

`rawdata`에 포함된 변수의 정의와 입력 기준을 정리한 코드북입니다.

코드북에는 변수명, 변수 유형, 허용값 또는 숫자 범위 등 검증에 필요한 정보가 포함되어야 합니다.

### 설정 후 재사용할 수 있는 파일

#### `settings.xlsx`

시트 연결, 대상자 식별 변수, 방문 변수, 제외 변수 등 QC 실행에 필요한 설정을 저장한 파일입니다.

#### `classification_reviewed.xlsx`

변수별 검증 유형과 허용값을 검토·수정한 결과를 저장한 파일입니다.

두 파일은 앱의 설정 단계에서 생성하여 다운로드할 수 있습니다. 최초 실행 시 한 번 설정한 후, 동일한 구조의 데이터에는 다시 업로드하여 재사용할 수 있습니다.

단, 연구 데이터의 구조나 코드북이 변경된 경우에는 설정 내용을 다시 확인해야 합니다.

## 3. 설치 및 실행

### 3.1 저장소 내려받기

```bash
git clone <repository-url>
cd <repository-folder>
```

### 3.2 가상환경 생성

Windows 기준:

```bash
python -m venv .venv
.venv\Scripts\activate
```

### 3.3 패키지 설치

```bash
pip install -r requirements.txt
```

### 3.4 앱 실행

```bash
streamlit run app.py
```

실행 후 웹 브라우저에서 안내된 주소로 접속합니다. 일반적으로 다음 주소가 사용됩니다.

```text
http://localhost:8501
```

## 4. 사용 방법

### 처음 사용하는 경우

1. `rawdata`와 `codebook`을 업로드합니다.
2. 시트 및 공통 변수 관련 설정을 확인합니다.
3. 변수 유형과 허용값을 검토합니다.
4. 방문 순서와 날짜 선후관계 규칙을 설정합니다.
5. 설정 결과 파일을 다운로드합니다.
6. 전체 검증을 실행합니다.
7. 화면에서 오류 건수와 상세 내용을 확인합니다.
8. 필요한 결과 파일을 다운로드합니다.

### 기존 설정을 재사용하는 경우

1. `rawdata`와 `codebook`을 업로드합니다.
2. 이전에 저장한 `settings.xlsx`와 `classification_reviewed.xlsx`를 업로드합니다.
3. 불러온 설정이 현재 데이터 구조와 일치하는지 확인합니다.
4. 전체 검증을 실행합니다.
5. 결과를 확인하고 다운로드합니다.

## 5. 변수 유형

| 유형          | 설명                               | `valid_value` 입력 예시 |
| ----------- | -------------------------------- | ------------------- |
| `choice`    | 입력 가능한 값이 정해진 변수                 | `0\|1\|2`           |
| `range`     | 입력 가능한 숫자 범위가 정해진 변수             | `0~10`              |
| `date`      | 날짜가 입력되는 변수                      | 비워둠                 |
| `free_text` | 성명, 비고 등 정해진 허용값 없이 자유롭게 입력하는 변수 | 비워둠                 |

코드나 범위가 정해지지 않은 자유입력 변수만 `free_text`로 설정합니다. 분류가 불확실한 경우 코드북의 입력 기준을 먼저 확인합니다.

## 6. 검증 결과 확인 방법

### 변수명 대조

코드북과 원본 데이터의 변수명이 일치하지 않는 항목입니다. 변수명 오탈자, 변수 누락 또는 시트 연결 오류가 있는지 확인합니다.

### 코드값 검증

코드북에 정의된 허용값이나 숫자 범위를 벗어난 항목입니다. 실제 오입력인지 확인하고, 정상적인 값이라면 변수 유형과 `valid_value` 설정이 올바른지 확인합니다.

### 방문 누락

대상자별 예상 방문 중 원본 데이터에서 확인되지 않은 방문입니다. 실제 미방문인지, 방문명 오입력 또는 데이터 누락인지 확인합니다.

### 공통값 비교

동일 대상자의 공통 정보가 시트마다 다르게 입력된 항목입니다. 각 시트의 값을 대조하고, 시트마다 달라도 되는 변수라면 비교 제외 설정을 확인합니다.

### 방문일 순서

방문일이 설정한 방문 순서와 맞지 않는 항목입니다. 방문명과 방문일을 확인하고, 같은 날 방문이 가능한 경우 관련 설정을 확인합니다.

### 날짜 선후관계

설정한 날짜 선후관계 규칙을 만족하지 않는 항목입니다. 원본 데이터의 날짜와 설정한 규칙을 함께 확인합니다.

## 7. 추출 결과 확인 방법

### `free_text_unique`

`free_text`로 분류된 변수에 실제로 입력된 내용을 보여줍니다.

같은 내용이 여러 번 입력되어 있더라도 결과에는 한 번만 표시됩니다. 예를 들어 비고란에 `특이사항 없음`이 여러 대상자에게 반복 입력된 경우, 결과표에는 해당 문구가 한 번만 나타납니다.

이를 통해 자유입력값의 오탈자, 표현 불일치 또는 예상하지 못한 입력값을 확인할 수 있습니다.

### `pattern_{시트명}`

각 시트에서 한 행에 입력된 값의 조합을 하나의 입력 형태로 보고 정리한 결과입니다. 여러 행의 입력 형태가 동일한 경우에는 대표 형태만 한 번 표시됩니다.

값의 종류가 많은 변수는 개별 값을 모두 표시하지 않고 `O`로 표시합니다. 현재 기준에서는 서로 다른 값이 5개 이상인 경우 `O`로 표시됩니다.

대부분의 행과 다른 예외적인 입력 형태를 살펴보면 다음과 같은 논리적 오류를 확인할 수 있습니다.

* 반드시 입력되어야 하는 값의 누락
* 동시에 입력될 수 없는 값의 조합
* 특정 조건에서만 입력되어야 하는 변수의 잘못된 입력
* 일반적인 입력 흐름과 다른 예외적인 형태

## 8. 결과 다운로드

### `QC_all_issues.xlsx`

검출된 전체 오류를 하나의 파일로 제공합니다. 검증 유형, 대상자, 변수명, 입력값 등의 정보를 확인하여 원본 데이터를 점검할 수 있습니다.

### 추출 결과 파일

`free_text_unique`와 시트별 입력 패턴 결과를 제공합니다. 오류 목록에 직접 포함되지 않은 자유입력값과 입력 조합을 추가로 검토할 때 사용합니다.

## 9. 사용 시 주의사항

* 본 도구는 규칙 기반으로 잠재적인 오류를 탐지하는 보조 도구입니다.
* 검출된 항목이 모두 실제 오류를 의미하지는 않습니다.
* 최종 판단은 코드북, 연구계획서 및 데이터 입력 기준을 함께 확인하여 수행해야 합니다.
* 입력 기준이 잘못 설정되면 정상값이 오류로 검출되거나 실제 오류가 누락될 수 있습니다.
* 데이터 구조 또는 코드북이 변경된 경우 기존 설정 파일을 그대로 사용하지 말고 다시 검토합니다.

## 10. 데이터 보안

이 저장소에는 실제 임상 데이터가 포함되어 있지 않습니다.

실제 데이터를 사용할 때는 다음 사항을 준수해야 합니다.

* Git 저장소에 원본 데이터나 결과 파일을 업로드하지 않습니다.
* 대상자 식별정보가 포함된 파일을 외부에 공유하지 않습니다.
* 기관의 개인정보보호 및 임상연구 데이터 관리 지침을 준수합니다.
* 필요한 경우 직접식별정보를 제거하거나 비식별화한 후 사용합니다.

민감한 파일이 Git에 포함되지 않도록 `.gitignore`에 다음 항목을 등록하는 것을 권장합니다.

```gitignore
*.xlsx
*.xls
*.csv
rawdata/
results/
uploads/
```

예시 파일을 제공해야 하는 경우에는 실제 임상 데이터가 아닌 임의로 생성한 가상 데이터만 사용합니다.

```text
project/

├── requirements.txt
├── README.md
├── .gitignore
```
