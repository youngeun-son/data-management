# Data Management 자동화 도구 사용 안내

## 도구 소개
Data Management 검증 도구는 rawdata와 codebook을 기준으로 DM을 자동 수행하는 Streamlit 기반 프로그램입니다. <br>
현재 페이지에서는 데모데이터를 기준으로 예시를 생성하였습니다.

---

## 사용 흐름
```text
→ Login
→ 파일 업로드
→ 연구 설정
→ 변수 분류 확인 및 수정
→ 날짜 규칙 설정
→ 전체 검증 실행
→ 오류 및 추출 결과 확인
→ 결과 다운로드
```

---

## 데모 데이터 소개
아래 예시는 `demo_data.xlsx` 파일을 기준으로 작성했습니다. 직접 열어서 각 시트를 확인하며 따라오시면 이해가 쉽습니다. ([demo_data.xlsx](./demo_data.xlsx))

| 시트명 | 설명 |
|---|---|
| 0_스크리닝 | 스크리닝 방문에서 수집하는 기본 정보 (동의일, 사고발생일, 성별, 나이 등) |
| 1_스크리닝_NRS | 스크리닝 방문의 NRS(통증 점수) 기록 |
| 2_OUTCOME_NRS | 추적관찰 방문(Visit1~3)의 NRS · VAS 결과 및 정보수집방법 |

| CODEBOOK | 위 시트들에 쓰인 변수의 이름 · 소속 시트 · 허용값(코드리스트) · 설명 · 데이터 유형을 정의한 코드북 |

## 툴 따라가기

### 1. 파일 업로드
Streamlit 화면에서 다음 파일을 업로드합니다.

**필수 파일**
* `rawdata`: DM을 수행할 원자료
* `codebook`: 변수명과 입력 기준이 정리된 코드북

**선택 파일**
이전에 동일한 구조의 데이터를 검증한 적이 있다면 다음 파일을 함께 업로드할 수 있습니다.
* `settings.xlsx`
* `classification_reviewed.xlsx`
* `date_rules.xlsx`

선택 파일은 최초 설정 과정에서 생성하여 다운로드할 수 있습니다. 이후 동일 연구 데이터에 다시 사용하면 설정 단계를 간소화할 수 있습니다.

---

### 2. 설정
업로드한 파일을 기준으로 DM에 사용할 시트와 주요 변수를 지정합니다.

#### 2-1. rawdata 컬럼 매핑
검증할 원자료 시트를 선택합니다. 데모 데이터에서는 다음과 같이 매핑합니다.

| 설정 항목 | 설명 | 데모 값 |
|---|---|---|
| Subject ID 컬럼 | 대상자 ID 컬럼을 선택합니다. | SUBJNO |
| 방문명 컬럼 | 방문차수 또는 방문명 컬럼을 선택합니다. | VISITNM |
| 방문일 컬럼 | 방문일 컬럼을 선택합니다. | VISITDT |
| 기준 시트 | Subject ID, 방문명 조합이 기준이 되는 시트를 선택합니다. | 1_스크리닝_NRS, 2_OUTCOME_NRS |

**기준 시트 선택 TIP**
* 연구의 주요지표 탭을 확인합니다. (예를 들어, NRS라면 방문별 NRS 탭을 확인합니다.)
* 주요지표 탭의 VISITNM을 확인합니다. (예를 들어, Visit1~연구종료 시점까지 있다고 가정합니다.)
* 주요지표 탭에 기재된 VISITNM 외 다른 VISITNM이 기재된 탭을 추가합니다. (예를 들어, VISITNM이 Screening로 기재된 탭이 있다면 추가해줍니다.)

#### 2-2. codebook 컬럼 매핑
검증에 사용할 codebook의 컬럼을 지정합니다. 데모 데이터에서는 다음과 같이 매핑합니다.

| 설정 항목 | 설명 | 데모 값 |
|---|---|---|
| 변수명 컬럼 | 변수명이 기재된 컬럼을 선택합니다. | 변수명 |
| eCRF명/시트명 컬럼 | 해당 변수가 속한 시트명(eCRF명)이 기재된 컬럼을 선택합니다. | eCRF명 |
| 코드리스트 컬럼 | 허용값 또는 범위가 기재된 컬럼을 선택합니다. | 코드리스트 |
| 항목명/설명 컬럼 | 변수의 한글 설명(라벨)이 기재된 컬럼을 선택합니다. | 항목명 |
| 데이터 유형 컬럼 (선택) | date, integer 등 데이터 유형이 기재된 컬럼을 선택합니다. 없으면 '(없음)'을 선택합니다. | 데이터유형 |

#### 2-3. 검증 옵션 (선택)
필요 입력 항목은 아니지만, 미입력 시 오류가 아닌 항목이 오류로 분류될 수 있습니다.

| 설정 항목 | 설명 | 데모 값 |
|---|---|---|
| 코드북 대조 및 값 검증 제외 변수 | 코드리스트에 없지만 문제없는 변수를 선택합니다. 여기 포함한 변수는 3번 코드리스트 분류 확인에서 반드시 free_text로 지정해야 합니다. | SUBJNO, VISITNM |
| 공통값 비교 제외 변수 | 동일 변수명을 쓰지만 시트마다 값이 달라도 되는 변수를 선택합니다. | LASTDT |
| 같은 날 방문 허용 | 방문명은 다르지만 방문일이 같을 수 있는 방문을 선택합니다. 입력 시에는 앞 순서의 방문 차수를 선택합니다. | Screening |
| 집계 임계값 | 같은 오류가 이 값보다 많으면 한 행으로 축약해서 보여줍니다. | 10 |
| 패턴 임계값 | 한 변수의 unique 값 개수가 이 값보다 많으면 'O'로 표시합니다. | 10 |

설정을 마치면 화면 하단의 **[현재 설정을 settings.xlsx로 저장]** 버튼으로 다운로드할 수 있습니다. <br>
다음에 같은 연구 데이터를 검증할 때 이 파일을 업로드하면 위 설정이 자동으로 채워집니다.

### 3. 코드리스트 분류 확인
codebook의 코드리스트 내용을 기준으로 각 변수를 choice / range / date / free_text 중 하나로 자동 분류합니다. <br>
classification_reviewed.xlsx를 업로드했다면 그 값을 그대로 보여줍니다.

| 유형 | 설명 | valid_value 입력 예시 |
|---|---|---|
| choice | 입력 가능한 값이 정해진 변수 | 0\|1\|2 |
| range | 입력 가능한 숫자 범위가 정해진 변수 | 0~10 |
| date | 날짜가 입력되는 변수 | - |
| free_text | 이니셜, 사유, 비고 등 정해진 허용값 없이 자유롭게 입력하는 변수 | - |

* 화면은 유형별 탭(choice / range / date / free_text)으로 나뉘어 있고, 탭 안 표에서 `codelist_type`과 `valid_value`를 직접 수정할 수 있습니다.
* 분류가 모호한 변수는 free_text로 두는 것을 권장합니다.
* 수정 후 **[분류 확정]** 을 눌러야 아래 검증에 반영됩니다.
* 확정한 분류는 **[분류 결과를 classification_reviewed.xlsx로 저장]** 으로 다운로드할 수 있습니다.


데모 데이터의 codebook을 그대로 두면 아래처럼 자동 분류됩니다.

| 변수명 | 자동 분류 결과 | valid_value | 비고 |
|---|---|---|---|
| SEX | choice | 1\|2 | - |
| AGE | free_text |  | - |
| PREGYN | choice | 0\|1\|7777 | - |
| CAUSEDDT | date | - | - |
| NRS | range | 0~10 | 코드리스트에 직접 기재한 값 그대로 반영됨 |
| VAS | range | 0~100 | 코드리스트를 비워둬도 자동 분류됨 (아래 참고) |
| VISIT_W | choice | 1\|2 | - |
| PGIC | choice | 1\|7| range로 수정필요 |

> [!TIP]
> NRS, VAS처럼 자주 쓰이는 평가지표는 코드북에 코드리스트를 채워주지 않아도(VAS처럼 비워둬도) NRS, VAS 입력값처럼 보이는 변수면 자동으로 range(NRS는 `0~10`, VAS는 `0~100`)로 분류됩니다.

> [!WARNING]
> **PGIC는 자동 분류 결과를 그대로 두지 말고 `range`로 직접 수정해야 합니다.** <br>
> 코드리스트에 "1=매우 많이 좋아졌다\|7=아주 많이 나빠졌다|"로 "="가 포함되어 있어 자동으로 `choice`로 분류됩니다. <br> 하지만 PGIC는 순서형 척도이므로 개별 값이 아니라 범위로 검증해야 합니다. <br> `choice` 탭에서 PGIC 행을 찾아 `codelist_type`을 `range`로, `valid_value`를 `1~7`로 수정한 뒤 **[분류 확정]** 을 눌러 반영하세요.

### 4. 날짜 선후관계 규칙 (선택)
3번에서 date로 분류한 변수끼리 "빠른 날짜 ≤ 늦은 날짜" 규칙을 만들어 확인합니다. <br>
date_rules.xlsx를 업로드했다면 그 규칙이 그대로 표시됩니다.

데모 데이터에서는 다음 규칙을 추가합니다.

| 빠른 쪽 (earlier) | 늦은 쪽 (later) | 관계 |
|---|---|---|
| 0_스크리닝 \| CAUSEDDT (사고발생일) | 0_스크리닝 \| VISITDT (방문일) | 1: ≤ (같은 날 허용) |

* 관계는 1(≤, 같은 날 허용) / 2(<, 같은 날 불허) / 3(=, 같은 날짜여야 함) 중에서 선택합니다.
* **[규칙 추가]** 로 여러 규칙을 계속 쌓을 수 있고, 표에서 체크 후 **[선택 규칙 삭제]** 로 지울 수 있습니다.
* 규칙 목록은 **[날짜 규칙을 date_rules.xlsx로 저장]** 으로 다운로드할 수 있습니다.

---

### 5. 전체 검증 실행
**[전체 검증 실행]** 버튼을 누르면 위에서 확정한 설정 · 코드리스트 분류 · 날짜 규칙을 기준으로 전체 검증이 한 번에 실행됩니다. <br>
기준 시트를 하나도 선택하지 않았다면 버튼을 눌러도 안내 메시지만 뜨고 실행되지 않으니, 2-1)에서 기준 시트를 먼저 선택하세요.

---

### 6. 결과
실행이 끝나면 아래 내용이 순서대로 표시됩니다.

#### 6-1. 검증별 오류 건수

| 검증 항목 | 설명 |
|---|---|
| 변수명 대조 | 코드북과 rawdata의 변수명이 일치하지 않는 항목 |
| 코드값 검증 | 코드북에 정의된 허용값·범위를 벗어난 항목 |
| 방문 누락 | 대상자별 예상 방문 중 rawdata에서 확인되지 않은 방문 |
| 공통값 비교 | 동일 대상자의 공통 정보가 시트마다 다르게 입력된 항목 |
| 방문일 순서 | 방문일이 설정된 방문 순서와 맞지 않는 항목 |
| 날짜 선후관계 | 4번에서 설정한 날짜 규칙을 만족하지 않는 항목 |

#### 6-2. 전체 오류 목록
검출된 모든 오류를 시트 · 변수 · 대상자 · 방문 · 값 · 메시지 형태의 한 표로 모아서 보여줍니다.

#### 6-3. 추출 결과 (free_text_unique / 값 패턴)
* `free_text_unique`: 자유입력 변수에 입력된 값을 중복 없이 정리한 목록
* `pattern_{시트명}`: 각 시트에서 행 조합의 중복을 제거하고 빈도를 보여주는 표. 첫 두 줄은 항목명 · 코드리스트 설명이며, 값이 5개 이상인 변수는 'O'로 표시됩니다.

#### 6-4. 결과 다운로드
* **all_issues 다운로드**: 전체 오류 목록을 `QC_all_issues.xlsx`로 저장
* **unique/패턴 다운로드**: free_text_unique와 pattern_{시트명} 결과를 `QC_unique.xlsx`로 저장
