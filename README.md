# DM QC 자동화 도구

임상연구 rawdata와 codebook(codelist)을 업로드하면 6가지 데이터 검증을 자동으로 수행하는 Streamlit 웹 도구이다.
Python을 다루지 않는 사용자도 브라우저에서 파일 업로드와 화면 설정만으로 검증할 수 있다.

## 1. 주요 기능

| 검증 항목 | 내용 |
|---|---|
| 변수명 대조 | codebook과 rawdata의 변수명이 서로 존재하는지 확인한다. |
| 허용값·범위 검증 | 선택형 변수는 허용 목록 포함 여부, 범위형 변수는 최소·최대 범위 내 여부를 확인한다. |
| 방문 누락 확인 | 기준 시트의 대상자·방문 조합과 비교하여 다른 시트에서 누락된 방문을 찾는다. |
| 시트 간 공통값 비교 | 기준 시트와 다른 시트에 공통으로 있는 변수의 값이 같은지 확인한다. |
| 방문일 순서 검증 | 방문 차수와 실제 방문일의 시간 순서가 일치하는지 확인한다. |
| 날짜 규칙 검증 | 동의일·등록일·방문일·종료일 등 사전에 정의한 날짜 간 선후관계 위반 여부를 확인한다. |

- 오류는 대상자·방문·행 위치와 함께 `all_issues`로 출력된다.
- 자유입력 고유값과 시트별 입력 조합은 `unique`로 출력되어 오탈자와 문항 간 논리 모순 검토에 활용한다.

## 2. 구성 파일

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit 웹 화면이다. 파일 업로드, 설정, 검증 실행, 결과 다운로드를 담당한다. |
| `qc_core.py` | 검증 로직 모듈이다. 6가지 검증 함수를 포함한다. |
| `requirements.txt` | 필요 패키지 목록이다. |
| `dm.bat` | Windows에서 서버를 실행하는 배치 파일이다. |
| `settings.xlsx` | 연구 정의 파일 예시이다. |
| `classification_reviewed.xlsx` | 코드리스트 분류 파일 예시이다. |

> `.streamlit/secrets.toml`(접속 비밀번호)과 실제 연구 데이터는 저장소에 올리지 않는다.

## 3. 설치 및 서버 실행 (관리자)

### 3.1. 패키지 설치

서버로 사용할 컴퓨터에 Python을 설치한 뒤 최초 1회 패키지를 설치한다.

```bash
pip install -r requirements.txt
```

필요 패키지는 `pandas`, `openpyxl`, `streamlit`, `streamlit-sortables`이다.

### 3.2. 서버 실행

`dm.bat`을 실행하거나 아래 명령을 프로그램 폴더에서 실행한다.

```bash
python -m streamlit run app.py --server.address=0.0.0.0 --server.port=8501 --server.headless=true
```

`dm.bat` 사용 시 파일 내 프로그램 폴더 경로와 `python.exe` 경로를 서버 환경에 맞게 수정한다.

### 3.3. 자동 실행 설정

Windows 작업 스케줄러로 매일 오전 9시 또는 시스템 부팅 시 서버가 자동 실행되도록 설정한다.

1. 작업 스케줄러에서 새 작업을 만든다.
2. 트리거를 `매일 오전 9시` 또는 `시스템 시작 시`로 지정한다.
3. 동작의 **인수 추가**에 `dm.bat` 경로를 지정한다.
4. **시작 위치**에 프로그램 폴더 경로를 지정한다.

## 4. 사용 방법 (사용자)

브라우저에서 `http://<서버 주소>:8501`로 접속하여 비밀번호로 로그인한다. 접속 주소와 비밀번호는 관리자가 공유한다.

전체 흐름은 6단계이다.

```
① 파일 업로드 → ② 설정 → ③ 코드리스트 분류 확인 → ④ 날짜 규칙(선택) → ⑤ 검증 실행 → ⑥ 결과 확인
```

### STEP 1. 파일 업로드

| 구분 | 파일 | 설명 |
|---|---|---|
| 필수 | rawdata.xlsx | 수집된 원본 데이터 |
| 필수 | codebook.xlsx | 변수 정의서(코드리스트) |
| 선택 | settings.xlsx | STEP 2에서 저장한 설정 파일 |
| 선택 | classification_reviewed.xlsx | STEP 3에서 저장한 분류 파일 |
| 선택 | date_rules.xlsx | STEP 4에서 저장한 날짜 규칙 파일 |

- 처음 사용할 때는 필수 파일 2개만 올린다.
- 같은 연구의 2차·3차 DM에서는 선택 파일 3개를 함께 올리면 STEP 2~4를 건너뛸 수 있다.

### STEP 2. 설정

웹이 rawdata의 시트·변수명과 codebook 컬럼 구조를 읽어 후보를 드롭다운으로 제시한다. 자동 입력값을 확인·수정한다.

- **rawdata 컬럼 매핑**: Subject ID, 방문명, 방문일 컬럼과 기준 시트를 지정한다.
- **방문 순서**: 방문명을 드래그하여 순서를 정한다. 이 순서가 방문일 순서 검증의 기준이 된다.
- **codebook 컬럼 매핑**: 변수명, eCRF명/시트명, 코드리스트, 항목명/설명, 데이터 유형 컬럼을 지정한다.
- **검증 옵션**: 같은 날 방문 허용, 제외 변수, 임계값을 지정한다.

완료 후 **[현재 설정을 settings.xlsx로 저장]**으로 저장한다. 항목별 설명은 [5.1](#51-settingsxlsx)을 참고한다.

### STEP 3. 코드리스트 분류 확인

codebook의 코드리스트를 `choice` / `range` / `date` / `free_text`로 자동 분류한다.

- 유형별 탭에서 `codelist_type`과 `valid_value`를 확인하고 필요 시 직접 수정한다.
- 확인이 끝나면 **[분류 확정]**을 누른다. 확정하지 않으면 수정 내용이 검증에 반영되지 않는다.
- **[분류 결과를 classification_reviewed.xlsx로 저장]**으로 저장한다.

### STEP 4. 날짜 규칙 (선택)

STEP 3에서 `date`로 분류된 변수로 날짜 선후관계 규칙을 만든다.

1. 빠른 쪽(earlier) 시트와 변수를 선택한다.
2. 늦은 쪽(later) 시트와 변수를 선택한다.
3. 관계(operator)를 선택한다.
4. **[규칙 추가]**를 누른다.

추가한 규칙은 표에서 확인·삭제할 수 있다. **[날짜 규칙을 date_rules.xlsx로 저장]**으로 저장한다.

### STEP 5. 검증 실행

**[전체 검증 실행]**을 누르면 6가지 검증이 순차적으로 수행된다.

### STEP 6. 결과 확인

검증 항목별 오류 건수와 결과 목록이 화면에 표시된다.

- **[all_issues 다운로드]**: 전체 오류 목록을 저장한다.
- **[unique/패턴 다운로드]**: 자유입력 고유값과 시트별 입력 조합을 저장한다.

## 5. 정의 파일

### 5.1. settings.xlsx

| 웹 항목 | settings 항목 | 내용 |
|---|---|---|
| Subject ID 컬럼 | `subject_col` | rawdata의 대상자 식별 변수 |
| 방문명 컬럼 | `visit_col` | 방문명 또는 방문 차수 변수 |
| 방문일 컬럼 | `visit_date_col` | 방문일 변수 |
| 기준 시트 | `base_sheets` | 대상자·방문 조합 비교의 기준 시트 |
| 변수명 컬럼 | `variable_col` | codebook에서 변수명이 기재된 컬럼 |
| 코드리스트 컬럼 | `codelist_col` | 허용값 또는 범위가 기재된 컬럼 |
| eCRF명/시트명 컬럼 | `form_col` | eCRF명 또는 시트명이 기재된 컬럼 |
| 항목명/설명 컬럼 | `res_col` | 항목명 또는 설명이 기재된 컬럼 |
| 데이터 유형 컬럼 | `data_type_col` | 데이터 유형이 기재된 컬럼 |
| 공통값 비교 제외 변수 | `exclude_cols` | 시트 간 공통값 비교에서 제외할 변수 |
| 코드북 대조/값 검증 제외 변수 | `skip_var_names` | 전체 검증에서 제외할 변수 |
| 같은 날 방문 허용 | `same_day_visits` | 같은 날짜를 허용하거나 순서 검증에서 제외할 방문 |
| 집계 임계값 | `aggregate_threshold` | 동일 유형 오류를 요약하는 기준 건수 (기본값 10) |
| 패턴 임계값 | `pattern_unique_threshold` | 고유값이 기준 이상이면 입력 여부로 요약하는 기준 (기본값 10) |

- 필수 항목은 Subject ID 컬럼, 기준 시트, 변수명 컬럼, 코드리스트 컬럼, 항목명/설명 컬럼이다. 나머지는 연구 구조에 따라 "없음"으로 둘 수 있다.
- `base_sheets`는 가능한 한 많은 방문이 포함된 시트(예: primary outcome 시트)로 지정한다. 여러 시트는 쉼표로 구분한다.

### 5.2. classification_reviewed.xlsx

| eCRF명 | 항목명 | 변수명 | 코드리스트 | codelist_type | valid_value |
|---|---|---|---|---|---|

- eCRF명·항목명·변수명·코드리스트는 settings에서 지정한 codebook 컬럼을 가져온다.
- `codelist_type`은 `choice`(선택형), `range`(범위형), `date`(날짜형), `free_text`(자유입력형) 중 하나이다.
- `choice`·`range`는 `valid_value`에 허용값 또는 범위를 기재한다.
- 결측 코드 `7777`/`8888`/`9999`는 검증 시 자동 허용되므로 `valid_value`에 표기하지 않는다.

### 5.3. date_rules.xlsx

| earlier_sheet | earlier_date | later_sheet | later_date | operator |
|---|---|---|---|---|

| operator | 의미 |
|---|---|
| 1 | earlier ≤ later (같은 날 허용) |
| 2 | earlier < later (같은 날 불허) |
| 3 | earlier = later (같은 날이어야 함) |

규칙 파일에 행을 추가하는 것만으로 새로운 날짜 조건을 검증할 수 있다.

## 6. 결과 파일

| 파일 | 내용 |
|---|---|
| all_issues.xlsx | 6가지 검증에서 오류로 판정된 항목을 대상자·방문·위치와 함께 출력한다. |
| unique.xlsx | `free_text_unique` 시트(자유입력 변수별 고유값)와 시트별 중복 제거 입력 조합을 출력한다. |

- `all_issues`를 검토하여 최종 DM log에 반영한다.
- `unique`는 자동 오류 판정이 아닌 참고 자료이다. 의심 항목은 rawdata와 입력 기준을 함께 확인하여 최종 판단한다.
- `unique`에는 대상자 단위 상세 정보가 포함되지 않는다.

## 7. Claude 스킬 연동 (선택)

Claude 팀 계정에 공유된 스킬 `dm-file-generator`로 정의 파일 작성과 unique 검토를 보조할 수 있다. 스킬은 rawdata를 직접 검증하지 않는다.

| 요청 예시 | 수행 내용 | 입력 파일 |
|---|---|---|
| "코드리스트 분류해줘" | classification_reviewed.xlsx 생성, 오분류·병합 누락 검토 | codelist |
| "날짜 규칙 만들어줘" | 연구계획서 근거로 date_rules.xlsx 초안 생성 | codelist 또는 검토된 classification + 연구계획서 |
| "unique 확인해줘" | 자유입력 오탈자·비정상값, 상위·하위 문항 논리 모순 제안 | QC 결과 unique 파일 |

**사용 순서**

1. Claude 창에 파일을 업로드한다.
2. `/dm-file-generator`로 스킬을 지정하거나 위 예시처럼 요청한다.
3. 생성된 정의 파일을 검토·수정한 뒤 웹 STEP 1에 업로드한다.
4. 검증 후 내려받은 unique 파일을 다시 스킬에 제공하여 추가 검토한다.

**주의**

- rawdata와 all_issues는 환자 정보가 포함되므로 스킬에 업로드하지 않는다.
- 날짜 규칙의 근거가 명확하지 않으면 '확인 필요'로 표시된다. 최종 지정은 사용자가 한다.
- 스킬 결과는 초안 또는 검토 의견이다. 최종 적용과 오류 판단은 사용자가 한다.

## 8. 예제로 따라 하기

예제 파일 `rawdata_예시.xlsx`, `codelist_예시.xlsx`로 전체 흐름을 연습할 수 있다. 6가지 검증 항목이 최소 1건씩 검출되도록 오류를 넣어 두었다.

**예제 데이터 구성** (시트 4개, 대상자 5명)

| 시트 | 내용 |
|---|---|
| 0_스크리닝 | 기본정보(성별, 나이, 임신여부, 사고발생일 등), Screening 1건 |
| 1_스크리닝_NRS | Screening 시점 NRS |
| 2_OUTCOME_PRI | Visit1~3 시점 NRS·VAS |
| 3_OUTCOME_PGIC | Visit3 시점 PGIC |

**STEP 2 입력값**

| 항목 | 값 |
|---|---|
| Subject ID 컬럼 | `SUBJNO` |
| 방문명 컬럼 | `VISITNM` |
| 방문일 컬럼 | `VISITDT` |
| 기준 시트 | `0_스크리닝`, `2_OUTCOME_PRI` |
| 방문 순서 | Screening → Visit1 → Visit2 → Visit3 |
| 변수명 / eCRF명 / 코드리스트 / 항목명 / 데이터 유형 컬럼 | `변수명` / `eCRF명` / `코드리스트` / `항목명` / `데이터유형` |
| 같은 날 방문 허용 | Screening, Visit1, Visit2, Visit3 |

**STEP 3 확인 사항**

| 변수 | 분류 | 조치 |
|---|---|---|
| NRS | range (0~10) | 그대로 둔다. |
| VAS | range (0~100) | 코드리스트가 비어 있으나 변수명 기준으로 자동 보정된다. |
| PGIC | choice (1, 7) | 실제 척도는 1~7이므로 `range`, `1~7`로 수정 후 [분류 확정]을 누른다. |
| PREGYN | choice | 화면에는 `0\|1`만 보이나 7777은 자동 허용된다. |

**STEP 4 규칙 예시**: `0_스크리닝.CAUSEDDT`(사고발생일) ≤ `0_스크리닝.VISITDT`(방문일), operator `1`

**STEP 6 예상 결과** (총 21건)

| 검증 항목 | 건수 | 예시 |
|---|---|---|
| 변수명 대조 | 10 | SUBJNO·VISITNM·SUBSTAT이 코드북에 없는 변수로 표시 |
| 허용값·범위 검증 | 1 | NRS = 11 (범위 0~10 초과) |
| 방문 누락 | 1 | 3_OUTCOME_PGIC에서 Visit3 누락 |
| 시트 간 공통값 비교 | 4 | SEX·VISITDT·LASTDT 값 불일치 |
| 방문일 순서 | 3 | Visit3 방문일이 Visit2보다 빠름 등 |
| 날짜 규칙 | 2 | 사고발생일이 방문일보다 늦음 |

`unique` 결과에서는 PREGYN(임신여부)과 SEX(성별) 간 논리 모순도 확인할 수 있다.

## 9. 유의점

- **기준 시트 자체는 방문 누락 검증에서 제외된다.** 다른 시트가 기준 시트의 방문 목록과 다를 때만 검출된다.
- **같은 방문 정보가 여러 시트에 나뉘어 있으면 "같은 날 방문 허용"에 해당 방문을 추가한다.** 추가하지 않으면 방문일 순서 오류가 대량으로 잘못 검출된다.
- **서로 다른 시트의 서로 다른 변수 간 조건부 논리는 검증하지 않는다.** (예: 시트1에서 약침 사용 = 예 → 시트2에 약침 종류 기록 필요) 이 항목은 rawdata에서 직접 대조한다.
- **모든 대상자에게 특정 방문이 통째로 없으면 방문 누락으로 검출되지 않는다.** 연구계획서의 측정 시점과 별도로 대조한다.
- **unique 결과와 Claude 검토 결과는 참고 자료이다.** 최종 오류 여부는 담당자가 판단한다.
